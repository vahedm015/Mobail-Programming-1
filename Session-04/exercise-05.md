# تمرین ۵: انتخاب فناوری

## بخش اول: طراحی معماری سیستم (سیستم ثبت درخواست مشتری)

**اجزای معماری:**
۱. **رابط کاربری (Frontend):** ساخته شده با فریم‌ورک Ionic (شامل HTML، CSS و JavaScript/TypeScript). شامل موارد زیر است:
   - فرم درخواست مشتری (نام، ایمیل، جزئیات درخواست).
   - لیست درخواست‌های ثبت شده (دریافت شده از سرور).
   - کامپوننت‌های رابط کاربری (دکمه‌ها، ورودی‌ها، کارت‌ها) بهینه‌شده برای موبایل.

۲. **قابلیت‌های موبایل (افزونه‌های Capacitor/Cordova):**
   - **API موقعیت مکانی:** از افزونه Geolocation برای دریافت مختصات فعلی کاربر (عرض و طول جغرافیایی) هنگام ثبت درخواست استفاده می‌کند.
   - **دوربین (اختیاری):** برای پیوست کردن عکس به درخواست.

۳. **بک‌اند/API (RESTful API):**
   - اپلیکیشن Ionic از طریق درخواست‌های HTTP (GET, POST) با سرور بک‌اند (مثلاً Node.js یا Python) ارتباط برقرار می‌کند.
   - ذخیره‌سازی داده‌ها (دیتابیس) برای درخواست‌های مشتریان را مدیریت می‌کند.

۴. **دیتابیس:**
   - داده‌های کاربر، جزئیات درخواست و مختصات مکانی را ذخیره می‌کند.

**جریان داده:**
کاربر فرم را پر می‌کند -> اپلیکیشن موقعیت GPS را می‌گیرد -> داده‌ها را به API می‌فرستد -> API آن را در دیتابیس ذخیره می‌کند -> اپلیکیشن لیست به‌روز شده را دریافت می‌کند.

## بخش دوم: چرا Ionic با Capacitor یا Cordova؟

**چرا Ionic؟**
۱. **کراس‌پلتفرم (Cross-Platform):** یک بار بنویسید، روی هر دو سیستم‌عامل اندروید و iOS اجرا شود (صرفه‌جویی در زمان و هزینه).
۲. **تکنولوژی‌های وب:** از زبان‌های استاندارد وب (HTML, CSS, JS) استفاده می‌کند که یادگیری و نگهداری آن‌ها آسان است.
۳. **کامپوننت‌های غنی رابط کاربری:** کامپوننت‌های آماده و شبیه به نیتیو برای موبایل ارائه می‌دهد.
۴. **جامعه بزرگ و اکوسیستم قوی:** از یک جامعه قوی و به‌روزرسانی‌های مستمر پشتیبانی می‌شود.

**Capacitor در مقابل Cordova (چرا یکی را انتخاب کنیم؟):**
- **Capacitor** جانشین مدرن Cordova است. توسط تیم Ionic توسعه یافته، عملکرد بهتری دارد، از استانداردهای وب مدرن پشتیبانی می‌کند و تجربه‌ای شبیه‌تر به نیتیو ارائه می‌دهد. برای پروژه‌های جدید توصیه می‌شود.
- **Cordova** قدیمی‌تر است و طیف گسترده‌ای از افزونه‌های قدیمی را دارد، اما به تدریج به نفع Capacitor کنار گذاشته می‌شود.

**عواملی که باید قبل از انتخاب نهایی ارزیابی شوند:**
۱. **نیازمندی‌های عملکردی:** آیا اپلیکیشن به گرافیک سه‌بعدی سنگین یا انیمیشن‌های پیچیده نیاز دارد؟ (در این صورت نیتیو ممکن است بهتر باشد).
۲. **بودجه و زمان:** کراس‌پلتفرم (Ionic) ارزان‌تر و سریع‌تر از ساخت دو اپلیکیشن نیتیو جداگانه است.
۳. **قابلیت‌های دستگاه:** آیا اپلیکیشن نیاز به دسترسی عمیق به سخت‌افزار (بلوتوث، دوربین پیشرفته) دارد؟ در دسترس بودن افزونه را بررسی کنید.
۴. **مهارت تیم:** آیا تیم با تکنولوژی‌های وب (JS/TS) آشناست یا با زبان‌های نیتیو (Java/Kotlin/Swift)؟
۵. **نگهداری بلندمدت:** اپلیکیشن‌های کراس‌پلتفرم به‌روزرسانی و نگهداری آسان‌تری دارند.
۶. **امنیت:** نیازمندی‌های امنیتی API و ذخیره‌سازی داده‌ها را ارزیابی کنید.
